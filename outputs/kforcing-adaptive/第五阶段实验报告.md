# 第五阶段：精度与评分方式尚未解释 k=4 复现差距

## 本轮结论

**在这组冻结样本上，把 k=4 推理改为 bf16/fp16 没有改善外部困惑度。缓存重用和训练/推理路径的局部核查也未发现能解释差距的错误。根因仍未定位。**

本轮完成 768 条生成记录：其中 256 条 fp32 控制精确重现第四阶段，512 条为新的精度对照。加上既有 AR 的 256 条输出，共 1,024 条序列，分别按 3 种明确定义的方式评分，产生 3,072 条评分记录。独立完整性审计通过，所有模型运行自然退出码为 0。

这轮缩小了排查范围，没有产生新的自适应算法收益；也没有根据这些诊断结果重新调控制器。

## 1. 如何隔离精度的影响

沿用第四阶段 128 个 LM1B held-out 前缀、种子 617/619、batch=4、tau=1、频率惩罚 0，固定生成 122 个新位置，离线在 EOS 截断。

每批预先生成 31 个 `(4,4,1)` CUDA 均匀噪声张量。公开 k=4 采样函数在 fp32、bf16、fp16 路径中重放完全相同的张量；fp32 控制必须逐 token 匹配旧输出才能继续。**256/256 条控制输出精确匹配。**

精度名称表示外层 autocast；权重保留 fp32，源码显式使用 fp32 的投影和 fp64 的正弦噪声特征保持原样。因此这项对照不能代表所有可能的低精度实现。

公开 `models/pflm.py` 与 CLI 文件和固定仓库版本的 SHA-256 相同；仍有先前明确记录的 Windows eager 辅助函数及 RoPE/SDPA 便携适配。

见[预先冻结的协议](STAGE5_PROTOCOL.md)、[噪声哈希清单](results/precision-005/noise_manifest.json)。还导出了[实际噪声数值](results/precision-005/replay_noise.json)，其 float32 字节哈希均与运行清单一致，便于换环境时沿用完全相同的外部输入。

## 2. 局部数值与缓存核查

选取前 32 个前缀，使用 fp32 控制生成的固定上下文，长度分别为 6/10/14/30/70；每个位置都固定噪声。这样比较的是同一个预测问题，而不是已经发散的两段文本。

| 对照 | 上下文案例 | 候选位置 | 首选 token 不一致 | 最大 logit 绝对差 |
|---|---:|---:|---:|---:|
| fp32 缓存 vs 完整上下文重算 | 160 | 640 | **0** | 0.0000916 |
| bf16 vs fp32，完整上下文 | 160 | 640 | 14（2.19%） | 2.44288 |
| fp16 vs fp32，完整上下文 | 160 | 640 | 2（0.31%） | 0.12823 |
| 训练 staircase 末窗口 vs 推理路径，fp32 | 16 | 64 | **0** | 0.0001450 |

最大差计算时排除了 mask token 的固定屏蔽值；它不是平均质量损失。训练路径核查使用 eval 模式、相同权重与噪声，不进行训练。

这些结果支持“已测缓存与窗口路径基本一致”。它们不是所有上下文、内核和精度组合的正确性证明；bf16/fp16 的缓存一致性没有在这一组局部比较中单独全面核查。

整段生成对数值变化更敏感：bf16 与 fp32 的 EOS 截断输出有 **172/256** 条完全相同，fp16 有 **247/256** 条。若比较包含 EOS 后计算的全部 128 个位置，相同数分别为 53 和 216。因此不能将所有后续 token 的不同都解释为独立的局部数值错误。

原始记录：[局部 logits 对照](results/precision-005/logit_diagnostics.json)、[检查汇总](results/precision-005/precision_checks.json)。

## 3. 外部质量评分

使用同一份经 SHA-256 校验的 GPT-2-Large、fp32、SDPA。每种方法 256 条输出；AR 沿用第四阶段生成，未改其精度或重新采样。主口径保持第四阶段的“只评分续写，不加 BOS，第一个 token 不计损失”，按有效 token 加权。

| 生成方法 | 主口径 Gen-PPL ↓ | 平均 BERT 新 token | 太短而排除的条数 |
|---|---:|---:|---:|
| AR，既有对照 | 102.25 | 25.07 | 0 |
| k=4，fp32 | **255.14** | 19.36 | 1 |
| k=4，bf16 | 259.50 | 19.07 | 1 |
| k=4，fp16 | 259.20 | 19.35 | 1 |

按前缀聚类保留两个种子，2,000 次配对 bootstrap：

- bf16/fp32 的 PPL 比：**1.017 [0.957, 1.088]**。
- fp16/fp32 的 PPL 比：**1.016 [1.001, 1.037]**。

这里没有发现将精度切换为 bf16/fp16 后质量大幅改善的迹象。fp16 的小幅劣化区间仅略高于 1；这些是未做多重比较校正的探索性区间，不能过度解读。主口径对既有 AR 和 fp32 k=4 共 512 条记录复评分，计分 token 数完全一致，NLL 数值差在预设容差内。

## 4. 评分方式能解释多少

同一组文本另做两项敏感性检查，全部列出，不选择更接近论文数值的一列充当复现结果。

| 生成方法 | 续写，无 BOS（主口径） | 前缀加续写，全部计分 | 续写前加 EOS 作为 BOS |
|---|---:|---:|---:|
| AR | 102.25 | 92.69 | 126.47 |
| k=4，fp32 | 255.14 | 191.73 | 321.18 |
| k=4，bf16 | 259.50 | 194.11 | 329.06 |
| k=4，fp16 | 259.20 | 194.28 | 326.15 |

“前缀加续写”同时改变预测上下文和计分 token 集；它不是“仅对续写计损失、以真实前缀为条件”的指标。BOS 列使用 GPT-2 的 EOS token 作为起始标记，首次计入续写首 token；原先只有 1 个 token 的输出在该列可以计分。

**评分约定会显著改变绝对 PPL，但已检查的三种约定均未消除 k=4 与 AR 的差距。** fp32 k=4/AR 的比值分别为 2.495、2.069、2.540。

论文附录描述了 EOS 截断、特殊 token 去除、GPT-2 重新分词和语料级加权；表 1 报告 LM1B k=4 为 127.6、AR 为 104.8。我们仍没有作者完整评分脚本与固定评测前缀，不应把这里的替代口径认定为作者实际口径，也不能据此断言作者结果错误。[论文表 1、附录 D.2](https://arxiv.org/html/2606.10820v1)

## 5. 这对自适应课题意味着什么

现在更有依据暂时降低两类怀疑的优先级：已测 fp32 缓存路径的大错误，以及“只要改成 bf16 就能恢复论文质量”。它们不能解释这组结果。

仍需核对的关键项是：公开权重与论文表格使用的训练版本是否对应、完整评测前缀与文本预处理、作者实际的 Gen-PPL 脚本，以及原始 Linux/FlashAttention 环境下的逐层输出。**根因未明确前，继续大量调自适应阈值很可能把基线差异当成算法空间。**

已整理[复现差异核对说明](复现差异说明_待作者核对.md)，包括固定版本、哈希、现象与具体问题。它是一份本地技术材料，尚未对外发送，也不指控原代码有缺陷。

这些 128 个前缀已经用于诊断，今后若据此修改方法，最终评估必须重新冻结独立测试集。本轮没有新增人类盲评、27B 裁判或可靠的低精度速度比较；Gen-PPL 仍只是一项外部语言模型指标。
