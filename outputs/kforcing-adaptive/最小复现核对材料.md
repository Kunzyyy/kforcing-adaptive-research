Dear K-Forcing authors,

Thank you for releasing the models and inference code. Before continuing an adaptive recomputation study, I would like to clarify a baseline reproduction difference. This is a configuration inquiry, not a claim of an error in the paper.

I use GitHub commit `706caa332a69d509b7fc2fa53ac7819f381a8c78` and HF revision `16b984316bdd4585f17b11d0e61a58d236c2febc`. The LM1B K4 checkpoint SHA256 is `3b013f0cf9a3acab4c20a1bb748beee6525432ef3f56a74df4957b898480a2c2`.

On 1,024 locally frozen LM1B prefixes, AR/K4 GPT-2-Large Gen-PPL is 114.39/215.71. The paper lists 104.8/127.6, but the original prefix list, exact checkpoint correspondence and complete evaluation script are not yet matched. My environment is Windows/RTX 5060 Laptop, torch 2.11.0+cu128, using portable SDPA/RoPE rather than the original H100 environment. AR follows the public CLI's internal fp16 path; PFLM uses fp32 without outer autocast. Generation uses batch4, temperature1, K4 penalty0 and 122 new positions. Completions stop at the first generated SEP; scoring strips BERT special tokens, retokenizes with GPT-2, adds no BOS and uses corpus token-weighted NLL.

Could you help confirm:

1. Which exact checkpoint hash and ordinary/EMA weights produced LM1B Table 1? Historical full checkpoints retain configuration and EMA, whereas the current slim checkpoint storage CRCs match the historical ordinary states.
2. Can you share the exact evaluation prefixes and generation/scoring script, especially precision/autocast, penalty, scoring interval and BOS handling?
3. Table4 describes RMSNorm while the released source calls F.layer_norm. Which implementation belongs to the reported checkpoint? Historical K4 metadata has global_step=150364 and trainer.max_steps=500000 with resume settings; how does that snapshot relate to the reported training stages? I am not treating the saved step counter as cumulative training duration.

Completed checks include cache/full-forward consistency, an independent finite forward probe, precision and scoring diagnostics, identical 30,522-entry vocabularies, matching encodings for all 1,024 source sentences, and identical decoding for 2,048 outputs. Restoring historical model configuration values produced identical outputs on 200 fixed cases and 64 complete generation pairs. A shape/order-checked historical EMA reconstruction did not improve K4 on a separate retrospective 128-prefix diagnostic; its original training parameter order remains unconfirmed.

If configuration alone does not explain the gap, the attached standalone probe runs 160 fixed PFLM cases/400 candidate positions in the official environment. It checks the exact checkpoint hash and makes no network requests. Matching these cases is a finite consistency check, not proof of distributional equivalence. No adaptive quality or speed advantage is claimed.

Thank you for any clarification.
