# 历史配置与分词器核查报告

2026-09-21。**历史分词器配置与加载器配置差异没有改变本轮受检输入的结果，尚不能解释论文基线差距。** 没有修改权重、既有解码算法或评分口径。

## 查了什么

上一轮恢复了完整检查点中的训练配置。本轮沿着这些真实字段做兼容性核查，没有再次搜索自适应预测器的小参数。

| 项目 | 范围 | 结果 |
|---|---|---|
| 历史 AR/PFLM 与本地词表 | 30,522 项 token→ID | 完全一致 |
| 慢速/快速 BERT 编码 | 第16阶段 1,024 个原始源句，含特殊token和截断 | 全部一致，冻结前缀也一致 |
| 生成文本解码 | 第16阶段 2,048 条输出 | 与旧文本全部一致 |
| 历史/当前配置的数值前向 | 160 个PFLM输入、40个AR输入 | logits/log-probs最大绝对差0；argmax均一致 |
| 递增上下文缓存 | 两模型各5批，长度6/10/14/30/70 | 缓存与输出最大绝对差0 |
| 完整生成 | 前32个旧源句×AR/K4，共64对 | 每条128 token与对应旧记录全部一致 |

固定前向覆盖PFLM的400个候选位置和AR的40个最后位置。缓存中的长上下文可能包含较早EOS，仅作数值检查，不作为文本质量样本。

## 字段为什么不同，结果却相同

| 字段 | 当前加载器 | 历史字段 | 当前发布源码中的作用 |
|---|---|---|---|
| cond_dim | 1024 | 128 | Transformer块及最终头接受此形参，但构造函数没有读取它 |
| scale_by_sigma | false | true | 被保存为属性；受检模型源码的推理路径不读取该属性 |
| AR dropout | 0 | 0.1 | `eval()`关闭dropout；不代表训练时两者等价 |
| PFLM gradient_checkpointing | 未填写 | false | 当前默认false；属于训练相关设置 |
| BOS/EOS分词器属性 | 默认None | CLS/SEP | 旧实验已显式使用101/102，实际前缀和停止规则一致 |

历史的训练恢复路径、教师路径等字段没有被执行。检查只把历史model字段用于实例化当前模型，再strict加载**同一套当前普通权重**。没有用恢复训练、换EMA或换模型源码来混入其他变量。

## 怎么核验

- [范围说明](CONFIG_TOKENIZER_AUDIT_PLAN.md)如实注明，词表和decode初查先于固定剩余核查范围；这是回顾性工程诊断，不是假称预注册的新实验。
- 历史pickle只由语法解释器读取，不执行旧对象；重建分词器使用本地transformers 4.55.0的受信任类。
- 旧数据、词表、权重、源码和固定输入由[manifest](results/config-tokenizer/manifest.json)锁定；前缀对应原始parquet行，并核对源句SHA256。
- [独立完整性检查](results/config-tokenizer/integrity_audit.json)复核全部记录及旧文件哈希，并在CPU独立构造模型，确认实际历史字段已生效、strict加载且所有模块处于eval模式。
- GPU前向和tokenizer算法没有重新独立实现；不把记录审计说成独立数值实现证明。

[分词核查](results/config-tokenizer/tokenizer_checks.json)与[模型核查](results/config-tokenizer/model_checks.json)均通过。此前结果和历史归档保持不变。

## 结论与下一步

在**当前源码、当前依赖和本地硬件**上，本轮受检配置和分词过程一致，没有证据支持修改现有加载器。原始训练代码、旧tokenizer库版本和H100环境尚未重现，不能把有限输入一致扩大为所有环境等价。

剩余优先核对信息仍是：论文表1对应的检查点hash/EMA选择、准确前缀与评分脚本，以及原始环境对固定输入的输出。我们已经把这些问题与证据集中到[给作者的最小核对材料](最小复现核对材料.md)，并生成一个不含模型权重的独立ZIP，尚未发送。

这项核查提高了复现材料的完整性，不构成新的自适应算法效果。现有自适应选择器仍未取得可靠的质量—速度优势。
