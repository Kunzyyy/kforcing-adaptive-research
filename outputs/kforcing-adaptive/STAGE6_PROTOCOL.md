# 第六阶段：公开版本核查与教师耦合的局部拆步诊断

在新局部实验结果产生前冻结。此次读取公开 GitHub/Hugging Face API，保存返回的版本、LFS 哈希和 issues 记录；未向任何人发送消息。

## 实验问题

在相同 LM1B 前缀和均匀噪声下，将一次 4-token 生成拆成两次 2-token，是否更接近公开 AR 教师逐 token 逆 CDF 采样的结果？已用前缀仅作为诊断集，不作为新方法独立测试集。

- 使用第四阶段 128 个固定 6-token 前缀，8 个预定种子：701/709/719/727/733/739/743/751，共 1,024 个窗口。
- fp32、tau=1、频率惩罚 0。每个前缀/种子用 CPU 固定发生器生成 4 个 uniform float32，均在模型运行前记录。
- AR 参考：每步根据已经生成的真实参考历史，计算公开教师 fp32 logits，以 float64 softmax/CDF 和对应噪声逆变换采样，连续 4 步。这与 multinomial 的随机耦合不同，但采用相同目标条件分布。
- PFLM 对照：一次 4 个候选；先 2 个再将实际候选加入上下文、用缓存生成后 2 个。噪声按位置共用，候选窗口不写入长期缓存。
- 保存逐位置 token、完整窗口是否匹配、首个分歧前长度、候选 top1-top2 间隔和 teacher EOS。主要汇总包括全部固定 4-token 窗口；另报告三个分支均无 EOS 的子集。EOS 后固定位置仅是映射诊断，不视为可见文本质量。
- 只比较一个既定信号：四候选尾部平均间隔越小，越倾向拆步。为检查同预算选择，按该信号排序选一半窗口（并列按 prompt_id/seed）；随机基线也恰好选择一半，用固定种子 60619。此为诊断集离线排序，非可部署的新控制器、非独立泛化检验。
- Oracle 在相同 50% 预算下，按“两步相对一步多匹配的教师 token 数”选择最大收益，作为读取答案的局部上界。不得声称实际解码可以免费获得这个上界。
- 按前缀聚类保留全部 8 个种子，2,000 次 bootstrap。报告总体拆步和信号相对随机的 token 匹配改善及区间；不根据结果新增信号或阈值。

## 边界

公开 k=4 模型是逐级蒸馏的产物，不要求其逐噪声输出与原始 AR 逆 CDF 映射严格相同。因此该一致度是特定噪声耦合下的诊断，**不是分布距离、似然或语义质量证明，也不是 k=4 的真实训练标签准确率**。没有重新训练、外部质量新结论或速度结论；所有比较都需后续在新数据、真实在线成本和独立质量指标下验证。
