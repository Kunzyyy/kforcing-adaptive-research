# 文本质量盲评：工具已完成，人工结果待收集

2026-09-21。

## 本轮解决了什么

已完成一个可离线使用的文本比较页面、与方法映射分离的评审包，以及收到评分后可直接运行的统计入口。当前人工评分为 **0**，质量结果为 **未评估**。

GPT-2 已经用于本项目的收益标签和候选选择，不能继续把它的改善当成人类文本质量得到验证。本轮为独立人工评价做好准备；没有训练新模型、生成新文本，也没有改变原先自适应选择器未通过确认的结论。

已有公开配置、分词器、普通权重和历史 EMA 排查仍未解释论文基线差距。在获得新的复现材料前，暂时结束同类排查；不能据此认定作者实现有错，也不能认定当前基线已经复现成功。

## 固定设计与实际抽样

详细约定见 [盲评方案](BLIND_QUALITY_PLAN.md)，生成前已保存并纳入输入哈希。

| 项目 | 本轮内容 |
|---|---|
| 数据来源 | 既有 decision-confirm 测试队列，共 5,448 对分支、681 个状态、380 个可用源句 |
| 主评价单位 | 随机抽 64 个不同源句；每源句随机取一个状态和一次未来续写 |
| 比较对象 | 保留四个候选 keep4 与保留前二、重算后二 split22 的一次干预 |
| 位置平衡 | 32 个主项 split22 在 A，32 个在 B |
| 展示内容 | 前文与包含该前文的完整解码文本；不展示方法、分数、原始 ID |
| 检查项 | 8 个 A/B 交换重复、8 个同文控制；合计 80 道题 |
| 主项自然同文 | 11 / 64，照常保留，不按文本差异挑选样本 |
| 人工评分 | 尚未收到；自动化测试答案全部排除 |

抽样程序没有读取质量标签或模型预测文件。另一个核查程序重建抽样、A/B 分配、控制项及题目顺序，并用慢版 BERT 分词器核对全部 128 段展示文本。两条路径一致。

完整文本与原来的单独续写字段可能有分词边界显示差异，因此页面统一从完整 token 序列解码，不手工润色模型输出。

## 工具和统计验证

- 页面支持 A / B / 相当 / 无法判断、两段都不可接受、选填理由、跳转、自动本地保存、JSON 导入与导出。
- 用隔离浏览器实际完成了导航、恢复进度、导出全部 80 项、错误评审包拒绝等 15 项检查。桌面与手机尺寸截图已人工目视检查；没有水平溢出、脚本错误或 HTTP 请求。这里的操作都是机器测试，不是人类评审。
- 14 项统计测试通过：已知方向的全胜/全负/平局、评审相反、缺失边界、48 个完整源句门槛、交换控制、重复代号、错误文件、合成数据拒绝等。
- 评审 ZIP 仅含 `index.html`、`tasks.json` 和使用说明，不含方法映射。所有文件与归档内容已核对哈希。
- 所有此前科学结果文件保持原样；只有项目总览和溯源说明增加本轮记录。

主指标是 split22 净偏好：胜为 +1、负为 −1、相当为 0；无法判断为缺失。先在每个源句内平均评审，再平均源句。至少 48 个源句具有全部评审的非缺失答案才计算主均值与 95% 源句重采样区间；同时报告缺失上下界、一致性，以及双方都不可接受的数量和分母。控制项表现不用于事后剔除评审。

## 如何真正完成这项评价

1. 由至少两名能够阅读英文文本的评审独立完成各自的 80 项。每人使用不同代号，不查看方法映射、GPT-2 分数和其他评审答案。
2. 只给评审 [评审专用 ZIP](../kforcing-blind-review.zip)。解压并用浏览器打开 `index.html`，可分次作答并导出进度。**不要给评审完整研究归档或 private 目录**，其中含解盲信息。
3. 收齐导出的完整 JSON 后，在工作区根目录按下列命令汇总。评审文件路径由实际文件替换；输出文件必须尚不存在。

```powershell
.\work\kforcing-env\Scripts\python.exe outputs/kforcing-adaptive/verify_blind_quality.py
.\work\kforcing-env\Scripts\python.exe outputs/kforcing-adaptive/analyze_blind_quality.py --ratings reviewer1.json reviewer2.json --out blind-quality-analysis.json
```

分析入口拒绝合成数据、缺少人工声明、重复代号、错误包、缺题和未完成进度。代号与人工声明只是自报；组织评审的人仍需要确认确有不同的人独立作答。不要把助手评分或 UI 测试的文件改名充当人工结果。

此包尚未对外发送。下一项实际所需输入是人工评审 JSON；收到以前不产生胜率、置信区间或质量提升结论。

## 这项评价能说明什么

它能描述这批源句上两种局部干预的人工偏好，不能直接证明19维选择器有效、不能说明相同运行时间下更好，也不能消除论文基线差距。样本量较小，区间仅反映源句抽样、条件于参与本轮的评审，不覆盖更广泛评审人群的变化。

即使人工结果偏向 split22，后续仍须解决“能否提前选对重算位置”和“收益是否抵得上计算成本”。如果结果不明确或没有改善，也应原样保留，不能因此更换样本再寻找正结果。
