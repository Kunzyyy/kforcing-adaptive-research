# 第三阶段：观察当前候选块，再选择提交长度

本协议在第三阶段评分/拟合前固定。基础模型冻结，不使用教师在线验收。

## 第一关：仅训练/开发数据

复用第二阶段的 train/dev 局部分支和教师标签，不使用第二阶段 test 做模型选择。重新运行当前 4-token 候选的同上下文/同噪声前向，核对生成 token 与保存记录一致，抽取决策时已经可见的当前候选块统计。

- 当前特征：四个位置各自的 top1−top2 间隔、熵、top1 概率，以及尾部两位置相对头部两位置的平均间隔差、平均熵差，共 14 项。
- 标签仍为 NLL(4)−NLL(2+2)。由于当前噪声已经可见，每个分支种子独立作为训练行；按文章划分，置信区间也按文章聚类。含 EOS 的分支保留记录但不进入标签拟合。
- 岭回归正则候选仅为 0.1、1、10、100，以开发集 MSE 选择；另一个预先固定候选是“尾部两位置的平均间隔越小越应缩短”。
- 两个候选按开发集约 50% 预算的选中收益增量排名，选较高者。该增量的文章聚类 95% bootstrap 下界大于零才进入新的测试实验；这是探索性筛选，不是最终显著性证明。
- 如均不通过，记录结果并停止本轮在线推进，保留未使用的新测试文章，不反复在开发集上换特征直到通过。

## 第二关：冻结控制器，再使用新测试文章

若通过第一关，将选定控制器、开发分数中位数阈值固定保存。用原开发前缀和固定种子 401、409 运行在线校准，得到随机提交策略的短步概率；不依据质量分数调整阈值。

新测试选 32 个前缀，每篇文章最多 4 个，来自 WikiText-2 test，排除第一阶段能由词表前缀匹配到的文章以及第二阶段全部测试前缀所属文章。若不足，显式停止，不复用已评估文章。排除所有先前前缀。

1. 新测试上先采集与第二阶段相同类型的局部分支，评价锁定分数的相关性和相对随机的离线选择收益。无论结果好坏，不重拟合；如已通过开发关，继续预定在线对照，完整记录两种评价。
2. 在线策略：固定 k=2/3/4、随机提交 2/4、锁定模型提交 2/4。自适应与随机策略每轮都计算最多 4 个候选，可能只提交前 2 个；丢弃尾部的计算计入耗时和候选数量。
3. 自适应首轮提交 4；之后根据当前候选的分数决定。随机首轮也提交 4，其余用开发校准的概率。固定策略只计算所需窗口，不能人为增加诊断开销。
4. fp32、频率惩罚 0、单请求、最大 64 个新 token、EOS 正常终止，随机噪声按输出位置索引。测试种子 503、509。每个 prompt/seed/策略计时重复 3 次，随机执行顺序；重复运行先合并，不能当作独立样本扩大样本量。
5. 计时包含预填充、模型、特征、CPU/GPU 传输、决策、缓存和 EOS。加载、分词、噪声预生成和离线教师评分不计入。固定/随机策略不计算未使用的置信度统计。

## 正确性与结论边界

检查缓存仅包含已提交的文本上下文、丢弃候选不进入缓存、窗口尾部、EOS，以及强制长/短提交与固定策略的 fp32 语义一致性。保存原始输出、决策、计算候选数、丢弃候选数、长度和评分。

局部标签筛掉 EOS、状态来自固定 4、每种子有限采样，在线状态分布会变化。教师 NLL 不等于人类质量；任何吞吐量提升都必须结合质量与长度解读。开发关筛选后，最终新测试仍可能失败；不宣称新颖性或教师采样分布保证。
