# K-Forcing 自适应解码：第一阶段实测

日期：2026-09-15。状态：探索性实验已产出；算法优势尚未成立；Windows 进程退出稳定性问题待解决。

## 先看结论

已经在本机 GPU 上加载官方权重，实现动态步长、缓存、校准、对照评估，完成 **20 个测试前缀 × 2 个种子 × 5 种策略，共 200 条真实生成**。

**本轮“上一轮置信度低，下一轮用短步长”的简单规则，没有显示出相对随机选择步长的可靠优势。** 不应把它包装成已经成功的新算法，或声称已经替 ZIP Lab 完成了尚未公开的研究。

本轮的价值是建立了可检查、可继续开发的实验起点，并发现一个具体问题：上一轮的原始 logit 间隔，可能无法很好地预测下一轮缩短步长的收益。

## 1. 实际完成了什么

- 使用官方 LM1B PFLM 检查点和 AR 教师检查点，固定下载 revision，核验完整 SHA-256；严格匹配模型参数，采用 `weights_only=True` 加载。
- 本机 RTX 5060 Laptop GPU，约 8 GB 显存；独立 Python 环境与 CUDA 版 PyTorch。没有使用付费云算力，没有修改系统 Python。
- 根据本轮选择传入 2 或 4 个噪声位置；缓存只保留已经进入文本上下文的内容，处理尾部不足整块和 EOS。
- 加入 fixed2、fixed3、fixed4、随机 2/4、自适应 2/4 五组对照。随机数按输出位置对齐，测试执行次序打乱。
- 在 validation 校准阈值和随机短步比例，test 不参与阈值调整。追加的收益诊断也只使用 validation。
- 保存原始输出、逐步选择记录、教师评分、环境版本、来源哈希、配对 bootstrap 和完整性审计。

代码入口见 [README](README.md)，实验约定见 [实验协议](EXPERIMENT_PROTOCOL.md)。这是冻结权重的推理实验，没有重新训练基础模型。

## 2. 第一轮结果

每种策略 40 条输出。PFLM 使用 bf16，教师离线评分使用 fp32。下表速度是本机单请求原型的聚合 token/s，包含预填充、策略、缓存和共同诊断开销；不能作为生产部署或论文硬件速度。

| 策略 | token/s | 教师 NLL ↓ | 平均生成 token 数 |
|---|---:|---:|---:|
| 固定 k=2 | 177.6 | 3.199 | 20.25 |
| 固定 k=3 | 262.8 | 3.832 | 18.93 |
| 固定 k=4 | 334.0 | 4.382 | 16.60 |
| 随机 k=2/4 | 273.8 | 4.083 | 20.53 |
| 自适应 k=2/4 | 277.5 | 4.073 | 18.58 |

教师 NLL 表示教师模型对这些生成文本的平均负对数似然；越低表示教师赋予的概率越高，**不直接等于文本更正确、更流畅或更多样**。所有输出均在 64 token 内遇到 EOS；输出长度不同也是比较中的混杂因素。

以 prompt 为聚类单位，保留同一 prompt 的两个种子，做 2,000 次配对 bootstrap：

- 自适应 / 随机的速度比：**1.014**，95% 区间 **[0.930, 1.104]**。
- 自适应 − 随机的教师 NLL：**−0.010**，95% 区间 **[−0.401, 0.412]**。

区间同时允许改善和退化，因此没有可靠优势证据，也没有证明两者等效。自适应比固定 k=2 快，但教师 NLL 明显上升，不能称为“保持质量的加速”。这些区间也不涵盖反复运行时的全部硬件波动。

原始证据：[样本 JSONL](results/pilot-001/samples.jsonl)、[统计分析](results/pilot-001/analysis.json)、[按前缀编号选取的文本样本](results/pilot-001/sample_review.md)。样本中存在语病和不连贯内容；重复率很低也不能据此判定生成质量良好。

## 3. 为什么当前规则可能不够好

规则使用上一轮平均 top1−top2 logit 间隔：间隔小则下一轮选 2，否则选 4。它需要成立的关键假设是：**这个信号能告诉我们“下一轮缩短步长到底值不值得”。** 置信度与这个收益并不是同一个量。

为检验这个假设，在验证集轨迹上抽取相同上下文，使用相同随机噪声，分别生成一次 4 个 token 和两次 2 个 token。分支关闭频率惩罚；包含 EOS 的分支被排除并记录。因此这个局部诊断与完整生成实验的条件并不完全相同。

全精度分支复查结果：44 对分支中保留 35 对，排除 9 对。上一轮间隔与“缩短步长带来的教师 NLL 改善”的 Spearman 相关为 **+0.109**；原假设期待的是负相关。低间隔组平均改善 1.281，高间隔组反而为 2.099。

**这批小样本没有支持当前选步信号。** 样本来自少量相关轨迹，排除 EOS 还会产生选择偏差；它不能证明这个信号在所有任务上无效。也不能从教师评分改善推出人类质量改善。

证据：[全精度局部分支诊断](results/pilot-001/signal_diagnostic_fp32.json)。

## 4. 正确性和仍未解决的问题

### 已验证

- 6 项小模型 CPU 测试通过：旋转位置编码的独立数学参考、因果前缀、变步长缓存、缓存/重算生成、EOS 和信号时序。测试输出头随机化，避免零输出造成虚假通过。
- 真实检查点 GPU fp32 预检查通过：缓存与重算最大差异为 0；短窗口与完整窗口对应前缀最大差异约 2.48×10⁻⁵。这是所测输入的结果，不是所有输入的数值保证。
- 不依赖 GPU 的完整性审计通过：200 个组合齐全、无重复、token/步骤计数一致、EOS 正确截断、数值有限、汇总重新计算一致、校准与测试前缀不重叠。

### 精度敏感性

最初 bf16 局部诊断中，有 1/44 对分支的前两个 token 不一致。在该输入上，变窗口带来的最大 logit 差异为 0.3125；改用 fp32 后差异降至约 2.77×10⁻⁵，前两个 token 一致。随后 fp32 分支复查的 44/44 对都保持前两个 token 一致。

这说明混合精度数值变化可能影响离散选词。主实验仍保留原始 bf16 结果，不把它们伪装为 fp32 重跑结果。未来正式比较需要增加精度敏感性实验。

### 退出异常尚未根治

主实验写完所有记录和汇总后，进程返回非零退出状态。两次双模型局部诊断也在打印完整结果后返回 Windows 状态 **−1073740791（0xC0000409）**；添加显式 CUDA 清理后仍出现。没有得到足以定位根因的 Python 异常栈，不能直接归因于某个库。

独立结果审计和单模型数值审计正常退出。前者证明文件完整，不能证明原运行过程或计时完全可靠。因此本轮速度只作探索性记录；开展更大实验前，应先稳定运行环境并重复测量。没有隐藏失败或用强制退出伪造成功状态。

证据：[真实检查点预检查](results/pilot-001/pretrained_checks.json)、[数值审计](results/pilot-001/numerical_audit.json)、[文件完整性审计](results/pilot-001/integrity_audit.json)、[测试记录](results/environment-tests.xml)。

## 5. 下一阶段怎样做才有用

建议按以下顺序推进；以下是后续计划，尚未宣称完成：

1. **稳定双模型运行与评价环境。** 最小化退出异常复现，定位依赖/驱动兼容问题；稳定后复测计时。必要时在实验室提供的 Linux GPU 环境对照。当前没有申请云资源。
2. **先做“步长收益能否预测”的研究。** 在新的训练/验证前缀上建立局部分支数据，比较最近位置的间隔、熵、跨步骤变化等低成本特征。特征只能来自决策前已经获得的信息，教师只用于离线标签与评价。
3. **采用简单模型检验信号。** 从逻辑回归或小决策树开始，按前缀划分数据；标签来自“缩短步长的收益”，同时考虑耗时成本。若对新前缀没有预测能力，就停止堆复杂控制器。
4. **重新建立独立测试。** 现有 test 已经被查看，后续不能反复拿它挑方法。增加 LM1B 同分布 held-out 数据、更多种子、长度受控计时、独立质量检查及同预算随机对照，再讨论质量约束下的加速。

对 ZIP Lab 更有帮助的交付，是一份能被复核的代码和证据：哪些条件下动态步长有收益、哪个信号能预测收益、工程实现的成本是多少。当前已经有第一版工具和不支持简单规则的初步证据；还没有足够结果宣称新方法成立。
