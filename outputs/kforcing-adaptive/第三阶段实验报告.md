# K-Forcing 自适应解码：第三阶段实测

日期：2026-09-15。已完成当前候选块的信号筛选、新文章验证和在线生成对照。

## 结论

**当前候选块的置信度在开发集上有效，但没有稳定泛化到新文章；在线策略也未显示出相对随机提交或固定 k=3 的优势。**

这次已经把“当前块自适应提交”实现为可运行代码，并实际计入特征计算、决策和被丢弃候选的开销。完成了 124 对新文章局部分支、320 条独立在线生成，每条计时 3 次，共 960 次运行。相关进程全部正常退出，数据审计通过。

我的判断是：现在应暂停继续改简单置信度阈值。保留这套基线，先核对同分布评测和质量评价，再决定是否需要更强的风险信号或训练改动；不能把开发集的漂亮结果当成新算法成立。

## 1. 本次方法与此前不同在哪里

此前在模型前向计算之前，使用上一轮统计量选择计算窗口。本次先实际计算当前 4 个候选 token，再决定提交前 2 个还是全部 4 个。

被舍弃的候选不进入长期文本缓存，但计算它们花费的时间已经发生。首轮提交 4 个；后续轮次根据当前候选块尾部两个位置的平均 top1−top2 logit 间隔决定。

开发集选定的最终规则为：**尾部平均间隔小于约 0.86245 时提交 2 个，否则提交 4 个。** 这个间隔是未校准的模型输出统计量，不能直接解释为错误概率。

另一个候选是用当前块的 14 项间隔、熵和 top1 概率特征训练岭回归。按照事先固定的开发集筛选规则，简单尾部间隔规则的收益增量略高，因此选择它；没有在测试之后改选回归模型。

源码：[commit_decoder.py](commit_decoder.py)、[current_features.py](current_features.py)；预先固定的方案：[STAGE3_PROTOCOL.md](STAGE3_PROTOCOL.md)。

## 2. 开发集通过了筛选，新文章没有复现

只重放第二阶段 train/dev 的 490 对候选，**490/490 与保存的候选 token 完全一致**，因此可以沿用对应教师标签。筛除 EOS 后，314 行用于训练，102 行用于开发，开发行来自 14 篇文章。每个分支种子作为一行，但置信区间按文章聚类，避免把相关行误当成独立样本。

| 场景 | 尾部间隔规则与短步收益的相关性 | 相对随机选一半的收益增量 | 95% 区间 |
|---|---:|---:|---:|
| 开发集 | 0.339 | +0.395 | [+0.093, +0.665] |
| 新文章局部测试 | 0.015 | +0.041 | [−0.155, +0.360] |

收益增量的单位为每 token 教师 NLL 差；不是人类质量分数。开发集区间下界大于零，通过了事先设定的探索性筛选。随后锁定规则与阈值，再开始新测试。开发集涉及候选选择，其区间不能当作最终显著性证明。

新测试来自前两轮未评估的 **16 篇文章、32 个前缀**。共采集 124 对分支，15 对包含 EOS，剩余 109 对用于局部代理评价；前两个 token 在所有分支对中均一致。

新测试区间覆盖零，因此没有可靠证据支持局部收益泛化。它也不能证明所有当前块信号都无效；本轮只检验了预先选择的这一个规则。

证据：[开发集筛选](results/current-003/screening.json)、[候选重放检查](results/current-003/replay_checks.json)、[锁定控制器](results/current-003/locked_controller.json)、[新文章排除记录](results/current-003/fresh_inventory.json)、[新文章局部结果](results/current-003/fresh_local_analysis.json)。

## 3. 在线生成：真实计入额外工作

使用相同新文章前缀、种子 503/509；每种策略 64 条独立生成，每条随机执行次序重复计时 3 次。先合并同一输出的计时，再按文章聚类计算区间，不能将 960 次运行说成 960 个独立质量样本。

硬件仍为本机 RTX 5060 Laptop GPU。fp32、频率惩罚 0、batch=1、上限 64 个新 token，遇 EOS 正常停止。固定 k 策略只计算所需窗口，不额外计算用不到的置信度统计。加载、噪声预生成和离线教师评分不计入；预填充、模型、特征、传输、决策、缓存、EOS 和丢弃候选的工作计入。

| 策略 | token/s | 教师 NLL ↓ | 平均输出长度 |
|---|---:|---:|---:|
| 固定 k=2 | 196.5 | 3.270 | 22.27 |
| 固定 k=3 | 296.6 | 3.809 | 19.48 |
| 固定 k=4 | 365.0 | 4.538 | 20.89 |
| 随机提交 2/4 | 293.5 | 4.297 | 19.20 |
| 当前块自适应提交 2/4 | 284.4 | 4.217 | 18.63 |

**主要比较：自适应相对随机提交**

- 速度比 **0.969**，95% 区间 **[0.900, 1.023]**。
- 教师 NLL 差 **−0.081**，95% 区间 **[−0.244, +0.102]**。

没有可靠的速度或教师评分优势。自适应相对固定 k=3 的点估计更慢，教师 NLL 还高出 0.407，NLL 差区间为 [+0.083, +0.732]。因此不能声称本方法超过了固定步长基线，也不能从相对 k=2 的速度提高推导出“保持质量的加速”。

原始证据：[汇总](results/current-003/online_summary.json)、[文章聚类分析](results/current-003/online_analysis.json)、[独立生成记录](results/current-003/online_samples.jsonl)、[全部重复计时](results/current-003/online_timings.jsonl)。

## 4. 两个容易误读的细节

### 实际短步比例不完全匹配

随机策略的短步概率只由开发集在线校准得到：400 个可决策轮次中有 199 次选择短步，所以锁定为 0.4975。没有根据测试质量重新调概率。

到了新测试，自适应在可决策轮次中的短步比例为 **53.16%**，随机策略实际为 **44.19%**。这受到新数据、随机波动和不同生成轨迹的影响。因此二者在测试中没有完全相同的实际预算；自适应略低的教师 NLL 也可能部分来自更多短步，不能全部归功于选得更准确。

### 候选数量不是 FLOPs

自适应为 1,192 个输出 token 计算了 1,648 个候选位置：其中 370 个被策略舍弃，86 个在已提交范围内因 EOS 而未输出。平均每个输出 token 对应 **1.383 个计算候选**。

随机提交为 1.328，固定 k=3 为 1.028。这个计数解释了额外工作发生在哪里，**不等于精确的 FLOPs 或耗时比例**；真实耗时仍以上表测量为准。

## 5. 正确性、稳定性与质量边界

- 3 项当前特征数学测试通过：概率单位、logit 平移不变性、仅使用候选尾部的规则。
- 4 项提交解码测试通过：原始固定窗口/始终短提交一致性、缓存/重算一致性、被丢弃尾部的 EOS 不提前终止、实际提交 EOS 的停止与工作量计数。
- 真实检查点的当前策略缓存/重算检查通过。
- 独立审计核对：无重复或遗漏的 960 个计时组合，320 条输出的 3 次重复 token 完全一致，计时正确合并，锁定控制器未变，候选/输出/丢弃数量相符，EOS 截断正确，汇总可重算。
- 新文章排除全部第二阶段测试前缀所属文章，并排除第一阶段可由 token 前缀匹配到的文章；另外检查所有先前前缀不重复。

相关进程自然退出码均为 0，第二阶段 Windows eager 辅助函数方案在这些运行中继续正常工作。它仍不能构成对所有运行环境的稳定性保证。

教师 NLL 和重复率都是代理指标。按前缀编号保存的样本仍有语病、不连贯和重复；本轮没有人工盲评，也不是官方论文的完整复现。[样本查看](results/current-003/online_sample_review.md)按前四个前缀展示所有方法与种子，没有按质量挑选。

证据：[特征测试](results/current-feature-tests.xml)、[提交测试](results/commit-tests.xml)、[真实模型预检查](results/current-003/online_preflight.json)、[独立审计](results/current-003/integrity_audit.json)。

## 6. 接下来的研究决策

三轮已经检验了两类方法：上一轮统计量预测下一轮收益，以及当前候选块决定提交长度。当前都没有达到值得宣称算法优势的证据标准。不能据此判定整个自适应方向无效，但继续在已看过的数据上调整简单阈值，价值有限。

更有价值的下一步是先补齐评价基础：

1. 在官方 LM1B 同分布设置中核对固定 k 基线和原作者评测口径，确认我们应解释的是方法局限、数据差异还是复现偏差。
2. 建立少量人工或其他独立质量评价，防止优化教师似然而生成质量没有改善。
3. 在训练/开发数据上检验新的风险目标是否可预测；只在它通过独立验证后考虑更复杂控制器或训练改动。

本轮的新测试文章已经被评估，今后不能再当作完全未见测试来挑方法。本地 WikiText-2 test 中，按当前保守排除规则只剩两篇未使用文章，不宜继续依靠它支撑多轮方法筛选。

现有交付可以作为后续工作的透明基线和复现工具。它还不是已经完成的科研创新；我们也不知道 ZIP Lab 的未公开内部进度。
