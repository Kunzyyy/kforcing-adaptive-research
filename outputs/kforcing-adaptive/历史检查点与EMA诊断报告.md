# 官方历史检查点与 EMA 诊断报告

日期：2026-09-21。**找回了原先缺失的训练元数据，但本轮 EMA 对照没有解释 K4 的质量差距。自适应方法仍未获得可靠优势。**

## 1. 本轮新增的证据

通过只读 API 核对了官方 GitHub 主分支全部27个祖先提交、Hugging Face 的11个历史 revision。当前代码、当前两份 LM1B 权重哈希仍与本地固定版本一致。此前浏览器工具无法获得精确版本的限制，本轮已通过API快照补齐；[原始记录](results/public-history/summary.json)和[采集程序](audit_public_history.py)可复查。

发现2026-06-10的早期完整检查点，随后发布为仅含 state_dict 的精简版本。历史 K4 文件约2.21 GB、当前约551 MB；历史 AR约2.11 GB、当前约528 MB。旧文件中保留了训练配置、普通参数、EMA和优化器元数据。来源：[历史模型revision](https://huggingface.co/zwave/K-Forcing/tree/6b357e2893399a3c0219df6ef62af8fc6af747a4)、[当前代码](https://github.com/alibaba-damo-academy/K-Forcing/tree/706caa332a69d509b7fc2fa53ac7819f381a8c78)。

EMA是训练过程中参数的指数滑动平均。训练时保留的普通参数与EMA参数可以不同，因此发布时选取哪套参数值得核对。

| 历史文件字段 | LM1B AR | LM1B PFLM K4 |
|---|---:|---:|
| global_step | 999412 | 150364 |
| epoch | 16 | 2 |
| trainer.max_steps | 1000000 | 500000 |
| EMA decay / num_updates | 0.9999 / 999412 | 0.999 / 150364 |
| eval.disable_ema | false | false |
| trainer.precision | bf16 | 32 |
| 普通状态张量数 / EMA参数数 | 101 / 100 | 109 / 108 |

保存步数不等于模型累计总训练步数，恢复训练可能重置计数；配置中启用了checkpoint恢复。以上不能证明论文训练流程有误，也不能证明表1采用了这份历史文件。需要核对实际训练阶段、累计步数与论文表格对应关系。论文训练与评测说明见[附录D](https://arxiv.org/html/2606.10820v2#A4)。

当前精简权重全部状态张量与历史普通参数的形状、存储字节数和CRC32一致；按参数顺序对应的EMA则全部不同。**这是元数据层面的对应证据，未下载历史全文件并验证其完整LFS SHA256。** [存储对照](results/public-history/storage_comparison.json)。

## 2. 代码历史排查

- 主分支历史文件清单中没有找到完整训练入口或独立Gen-PPL评分脚本；包含模型内的训练相关方法，这不等于完整训练流程已经发布。
- 早期一版曾为候选位置加入额外温度采样，随后被移除，并加入频率惩罚。当前无惩罚设置与已测惩罚0.5仍是既有诊断，不把旧采样启发式当作论文设置。
- 8月依赖升级对三个模型源文件的方法改动，在仅规范化CUDA autocast API写法后AST一致。此结果不能排除依赖库数值差异。
- LayerNorm/RMSNorm对应问题仍待核对。没有擅自替换归一化。

## 3. 冻结的小规模 EMA 对照

按[预先写入的方案](HISTORICAL_EMA_PLAN.md)，使用第16阶段旧1024源句的前128条。每模型用相同前缀、batch=4、相同种子生成122个新位置；首EOS截断、tau=1、K4惩罚0。AR保持公开CLI内部fp16，PFLM保持fp32。GPT-2-Large fp32评分，仅续写、无BOS、语料token加权。

EMA是未带参数名的列表。本轮按历史 state_dict 的参数顺序、去掉 rotary buffer，逐项核对形状/步幅/类型，并确认与发布模型 named_parameters 顺序一致；旧训练代码中的真实EMA注册顺序仍未获得确认。因此这是**按可核对顺序恢复的历史EMA诊断**。

| Gen-PPL（越低越好） | 普通参数 | 历史EMA | EMA/普通参数比值，95%描述区间 |
|---|---:|---:|---|
| AR | 121.64 | 115.18 | 0.947 [0.781, 1.129] |
| K4 | 256.79 | 267.39 | 1.041 [0.896, 1.197] |

K4的EMA−普通参数平均token NLL为+0.04045，95%描述区间[−0.10937, 0.17973]；AR为−0.05457，[−0.24774, 0.12125]。两者区间均跨零。128源句上的K4 EMA没有改善基线，不支持“直接换回这套EMA就能解决差距”。这也不排除其他checkpoint版本、准确EMA映射或评价设置的影响。

这些数值来自**128条子集**，不能与上一轮1024条的114.39/215.71直接作配对比较。本轮是回顾性诊断，没有独立新测试、自适应提速或严格论文复现结论。[完整统计](results/historical-ema/analysis.json)。

## 4. 校验与执行范围

- 256条新EMA生成，复用256条普通参数记录；512条统一重新评分。
- 普通参数首批8条的完整128 token重现；旧256条评分总NLL最大绝对差为0。
- 提取的208个EMA参数逐项CRC32/SHA256、有限值、形状、strict加载通过；旋转位置buffer保持原值。
- 512条源句、种子、EOS、文本、评分token数检查通过；两组4000次配对源句bootstrap由独立计算复核。
- 自写pickle语法读取器在本地检查点全部张量上对照验证；历史对象未被反序列化执行。
- [完整性审计](results/historical-ema/integrity_audit.json)通过；此前科学文件和旧ZIP保留。

执行范围修正：方案写“只下载EMA、不下载优化器状态”，实际为减少HTTP请求下载了覆盖EMA的连续字节区域。因此除约1.079 GB EMA tensor数据外，也传输了夹在区间内的约68.51 MB其他数据/头部。仅提取、使用EMA张量，没有加载优化器对象。两模型区间共约1.147 GB，均记录在提取清单；未下载4.318 GB完整历史文件。此差异不影响冻结的生成/评分方案，但需要如实记录。

## 5. 研究决策

保留当前公开权重作为既有结果对应版本，不因这一轮改写以前的自适应结论。停止把EMA单独当作已验证修复。新的作者核对重点是：**表1检查点的确切hash、是否EMA、训练阶段/计数、真实评测前缀与脚本**。

已准备[更新的作者核对材料](作者核对补充_历史检查点与EMA.md)，仍未发送。旧固定输入工具针对当前发布权重，可继续用于原始环境对照。当前成果增加了一项可复查的版本诊断与阴性对照，没有产生新的自适应算法成功结论。
