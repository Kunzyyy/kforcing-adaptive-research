# 第四阶段：官方口径审计与 LM1B 同分布基线

目的：核对前三阶段与作者设置的差异，并建立独立评分基线。本轮不再调自适应控制器。

## 已核对的区别

论文主评测使用 LM1B held-out 前缀、6-token 前缀补全到总长 128、固定长度吞吐量、外部 GPT-2-Large Gen-PPL，并另有 Qwen3.5-27B 裁判。此前是 WikiText-2、最多 64 新 token、EOS 提前停止、教师 NLL、单请求。官方公开 CLI 与论文还存在细节差异：AR 内部强制 fp16，而论文描述吞吐量使用 bf16；PFLM CLI 没有显式外层 autocast。

来源：[论文 §4.1 与附录 D.2](https://arxiv.org/html/2606.10820v1)、固定版本的 `upstream/batch_inference_with_prefix.py`。

## 数据与主要实验

- 下载固定 revision 的 Hugging Face 官方 LM1B held-out parquet 转换文件，核验公开 LFS SHA-256。
- 固定随机顺序选择 128 个不重复的前缀，排除既往前缀；BERT uncased、CLS 加 5 个 wordpiece。另保留同一原句的参考续写用于评分参照。
- 主要质量样本：AR、PFLM k=2/3/4，batch=4，每个前缀种子 617/619，共 1,024 条生成。PFLM 频率惩罚为 0，temperature=1。
- 固定生成 122 个新 token，不在 EOS 停止计算；保存完整 ids，在离线评价时从第一个生成 EOS 截断。分开记录固定生成位置和截断后有效输出。
- 使用原作者采样函数和 AR CLI 缓存采样逻辑，只进行既有便携 RoPE/eager 辅助函数适配。采用公开 CLI 的原生精度路径（AR fp16、PFLM 无外层 autocast），明确不冒充论文统一 bf16/H100/FlashAttention。
- 计时补充：batch=4/16，在同一批 128 个前缀上每个方法测量 3 次，随机轮换方法次序；one warm-up；记录自然退出码。质量样本也参与重复计时，但不把重复输出算作新的独立质量样本。
- 主要 Gen-PPL：外部 GPT-2-Large，fp32；只评分去特殊 token 的续写，重新分词，使用无 BOS 的常规 shift NLL，第一个 GPT-2 token 不计分；少于两个 GPT-2 token 的输出记录并排除。报告 token 加权 NLL 的指数。
- 同时评分真实参考续写、旧第三阶段 320 条输出以及当前同分布基线。旧数据的外部评分属于审计，不用于重新选择控制器。
- 对新的主要样本保留教师 NLL 作为旁证，绝不与外部 GPT-2 PPL 混称。外部评分依然不是人类质量保证。

## 正确性核查

在同一固定噪声 tape 上对比原作者采样函数与我们的固定窗口实现，检查 token、频率惩罚、KV、EOS 和尾部长度；对 AR 缓存最后一步与完整上下文评分做同精度核对。审计 tokenizer 对官方示例前缀是否一致。论文表格数值只作背景，不据不同硬件、精度、样本数得出的结果宣布复现成功或失败。

不运行 27B 裁判，不假冒人工评价；不申请付费服务。公开论文没有发布全部固定评测前缀、完整评分脚本和所有细节，因此本轮仍是部分复现与诊断。

## 在外部评分前追加的公开配置敏感性检查

核对 `scripts/run_pflm_lm1b.sh` 后发现作者为 k=2/3/4 分别建议频率惩罚 0.2/0.4/0.5。因此在保留主要无惩罚基线的同时，对同一 128 个前缀、617/619 两个种子、batch=4，按这三个公开数值额外生成 768 条输出，只运行一次。该配置来自源码建议，不根据结果选值；单次补充耗时不当成重复计时结论。外部评分同时报告两组，不隐去表现较差的一组。
